# What people complain about in other IDEs

A short survey done before Phase 1 (September 2026) of recurring complaints
about Python and data-science IDEs, and the SPAWN decision each one led to.
This is not exhaustive; it is the list that shaped the design.

| Complaint                                                                                                                                     | Where it shows up                                                                                                                                                                                                                                                                                                                                             | SPAWN decision                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Code runs in a separate terminal or console; switching between code and results is tedious.                                                   | [Saturn Cloud on Jupyter vs VS Code](https://saturncloud.io/blog/jupyter-notebook-vs-vscode-which-is-better-for-data-science/)                                                                                                                                                                                                                                | Output, tracebacks and `input()` prompts stream into a panel under the editor. Nothing opens a terminal. Hard requirement from Phase 1.                                                                      |
| Beginners cannot tell which interpreter the run button used, and `input()` "doesn't prompt" when run from the IDE.                            | [Coddy on running Python](https://coddy.tech/docs/python/run-python-script), [discuss.python.org](https://discuss.python.org/t/input-function-errors-help/11746)                                                                                                                                                                                              | The output panel header shows the exact command line. Python runs unbuffered (`-u`, `PYTHONUNBUFFERED=1`) so prompts appear immediately. The status bar always shows the interpreter and where it came from. |
| Debuggers show tensor values, not shapes; typing `x.shape` for every tensor is slow.                                                          | [JetBrains support thread](https://intellij-support.jetbrains.com/hc/en-us/community/posts/360009791140-Show-torch-tensor-shape-instead-contents-in-PyCharm-debugger), [debugpy discussion #1199](https://github.com/microsoft/debugpy/discussions/1199), [PyTorch forums](https://discuss.pytorch.org/t/tensor-repr-in-debug-should-show-shape-first/147230) | The tensor inspector is a flagship feature: hover shows shape, dtype, device, min/max/mean and a heatmap. Shape mismatches are the thing to make visible.                                                    |
| Variable explorers in VS Code "don't feel or look good" next to Spyder's; PyCharm's DataFrame viewer is paid; explorers die with the session. | [vscode-jupyter issue #1148](https://github.com/microsoft/vscode-jupyter/issues/1148), [Spyder docs](https://docs.spyder-ide.org/current/panes/variableexplorer.html)                                                                                                                                                                                         | Phase 2 adds a variables pane over the pool's namespace and a real DataFrame viewer, free, in the core app.                                                                                                  |
| Consoles that "stop working until restarting"; View() bugs; sessions that silently die.                                                       | [Positron review](https://ntluong95.github.io/profile/blog/2024-12-04_positron_review/), [BigGo on Positron](https://biggo.com/news/202508200115_Positron_IDE_Mixed_User_Reviews)                                                                                                                                                                             | The pool gets an explicit restart command and a visible health indicator in the status bar. Kernel death is a state the UI shows, not a mystery.                                                             |
| Webview visualization panels are sluggish; large outputs freeze the UI.                                                                       | [Hacker News on Positron](https://news.ycombinator.com/item?id=44951862), [JupyterLab 4 notes](https://pristren.com/blog/jupyter-lab-vs-vs-code/)                                                                                                                                                                                                             | The output model is bounded (ring buffer) and batched per animation frame from day one. Inline plots render as images or lightweight SVG, not full plotting runtimes in the DOM.                             |
| Data viewers cannot explore nested lists and dicts as trees; labeled data unsupported.                                                        | [Dr. Mowinckel on Positron](https://drmowinckels.io/blog/2025/positron-debugging/)                                                                                                                                                                                                                                                                            | Phase 2 object inspector handles dicts and lists as trees, not only tables.                                                                                                                                  |
| Debugger quirks: pasted multi-line code hangs the console, focus jumps to read-only views.                                                    | [Dr. Mowinckel on Positron](https://drmowinckels.io/blog/2025/positron-debugging/)                                                                                                                                                                                                                                                                            | Phase 4 is scoped to DAP basics done well (breakpoints, stepping, variables) rather than a wide surface.                                                                                                     |
| Positron's Elastic License is "not open source"; hosted-use restrictions block academic deployment.                                           | [BigGo on licensing](https://biggo.com/news/202507270752_Positron_IDE_Licensing_Criticism), [Hacker News](https://news.ycombinator.com/item?id=44951862)                                                                                                                                                                                                      | MIT.                                                                                                                                                                                                         |
| Positron on Linux is "slow and buggy" for early users.                                                                                        | [Positron review](https://ntluong95.github.io/profile/blog/2024-12-04_positron_review/)                                                                                                                                                                                                                                                                       | Linux is the maintainer's daily platform and the first one tested. The WebKitGTK blank-window case has an opt-in workaround (`SPAWN_SAFE_RENDER=1`).                                                         |
| Electron apps are large and start slowly.                                                                                                     | general, and the maintainer's own Wayland experience                                                                                                                                                                                                                                                                                                          | Tauri: system webview, a binary of a few megabytes. The trade is three rendering engines to test instead of one.                                                                                             |

## What SPAWN deliberately does not chase

Language intelligence and debugging parity with VS Code or PyCharm. Those have
thousands of engineer-years behind them. SPAWN aims to be excellent at the
run-and-inspect loop for ML work and solid everywhere else.
